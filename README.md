# PersonaForge

PersonaForge is a desktop AI chat app for Windows that runs entirely on your own machine. You pick one of three personas (Assistant, Tutor, Thinker), point it at a local Ollama model, and chat. There's a creativity slider that controls how literal or wild the responses are, optional DuckDuckGo web search if you want the model to look things up, and on device text to speech with voice cloning through Coqui XTTS v2. No API keys, no cloud calls, nothing leaves the laptop.

## What it does

The three personas each have their own colour theme, ten system prompt presets that scale with the creativity slider, and a set of in character refusal messages. Assistant at creativity 1 is terse and factual. Assistant at 10 is freewheeling and speculative. Tutor at 1 drills you. Tutor at 10 takes a Socratic approach. Thinker generates a few safe ideas at the low end and sci fi grade speculation at the top.

The creativity slider does two things at once. It picks which of the ten prompt presets the model gets, and it sets a random refusal probability of `level * 10%`. So at level 7, roughly 70% of the time the model answers normally, and 30% of the time you get a short, in character "no" instead. That sounds annoying on paper, but in practice it gives the persona a real presence. You can feel the difference between a Tutor refusal ("Tell me what you already know about the topic") and a Thinker one ("Give me one constraint to anchor against").

Chat streams over SSE from FastAPI to the React frontend, conversations save to SQLite, titles get autogenerated in a background thread after the first few messages, and the sidebar lets you rename or delete past chats.

For web search, toggle the switch in the sidebar and ask anything time sensitive. The backend runs a DuckDuckGo query (news and text, past week), prepends the results to the model's context, and shows them in an expandable card under the reply.

For voice, click the speak button on any reply. If you've dropped a clean 5 to 15 second WAV at `voices/assistant.wav` (or `voices/tutor.wav` or `voices/thinker.wav`), XTTS clones that voice for the synthesis. If you haven't, it uses XTTS's built in default speaker, and TTS still works out of the box.

## The interesting engineering bit

I'm running this on a laptop with 8 GB of VRAM, which isn't enough to keep Ollama and XTTS v2 in memory at the same time. So I wrote a small GPU coordination layer that gates all GPU work behind a single thread lock. When you click speak, it grabs the lock, tells Ollama to unload via `keep_alive=0`, loads XTTS, runs synthesis, then drops XTTS and frees the VRAM. On the next chat message, Ollama auto reloads. It's not magic, but it makes the whole thing feel like both models live in memory when really they're taking turns.

The other slightly tricky thing was how to inject the persona prompt. Ollama's `/api/chat` treats a `system` role message as a wholesale replacement for any Modelfile SYSTEM directive, which means if you ever swap in a custom Modelfile, the persona gets overridden. So instead I prepend a fake `user`/`assistant` exchange at the start of the message list that carries the persona instructions, and the model picks up the style without losing whatever the Modelfile set. Refusal messages also get filtered out of the history before being sent back to the model. Otherwise the model starts mimicking them.

## Tech stack

Frontend is React with TypeScript, Tailwind, and Framer Motion, all bundled with Vite. Backend is Python 3.10+, FastAPI, and SQLModel on top of SQLite. The LLM layer is Ollama (`/api/chat`, streaming). Web search uses the `duckduckgo-search` package. TTS is Coqui XTTS v2 running on CUDA. The desktop shell is Electron, and the Windows installer is built by PyInstaller (for the backend exe) plus electron builder (for the NSIS installer).

## Setup

You'll need Python 3.10+, Node 18+, Ollama running locally, and optionally an NVIDIA GPU with CUDA if you want TTS to work.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

npm install
npm --prefix frontend install

ollama pull llama3.1:8b
```

To run it in dev mode:

```powershell
.\run_app.bat
```

That spawns the backend, Vite, and Electron in one go. If you'd rather split them across windows:

```powershell
.\run_backend.bat
.\run_frontend.bat
```

The frontend dev server lives at `http://localhost:5173` and the backend at `http://127.0.0.1:8123/api`.

## Building the installer

```powershell
.\build_windows.ps1
```

That runs PyInstaller on the backend, builds the frontend, and wraps everything up with electron builder. You'll get an NSIS installer in `dist/`. One caveat: the bundled exe excludes TTS, Torch, and Transformers, because packaging those on Windows is its own multi day project. So in the installed app voice cloning won't work, though chat, web search, and persona switching all do.

## Config

`config.yaml` at the project root holds the defaults:

```yaml
app:
  data_dir: data
  log_level: INFO

ollama:
  base_url: http://127.0.0.1:11434
  default_model: "llama3.1:8b"
  temperature: 0.7
  max_tokens: 1024

creativity:
  default_level: 3
  web_search: false
```

You can override the Ollama settings with `OLLAMA_BASE_URL` and `OLLAMA_DEFAULT_MODEL` environment variables if you'd rather not edit the file.

## API

| Method | Path | Notes |
|---|---|---|
| `GET` | `/api/status` | health check |
| `GET` | `/api/models` | Ollama models |
| `GET` / `POST` | `/api/settings` | app settings |
| `GET` | `/api/personas` | persona metadata |
| `POST` | `/api/chat` | non streaming chat |
| `POST` | `/api/chat/stream` | SSE streaming chat |
| `GET` / `POST` / `DELETE` / `PATCH` | `/api/conversations[/{id}[/messages]]` | history CRUD |
| `POST` | `/api/tts` | text to WAV |
